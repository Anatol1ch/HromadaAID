# Ручне резервування та відновлення

## Звичайне відновлення

1. Адміністратор відкриває **Налаштування → Резервне копіювання**. Ручна копія створюється кнопкою «Створити резервну копію»; її можна завантажити незалежно від дозволу цього комп’ютера на автоматичне резервування.
2. Для відновлення виберіть серверний архів або локальний `.hraid`. Файл передається через Electron main; ключ залишається на сервері.
3. Перевірте дату, попередження про втрату пізніших змін та підтвердьте. Сервер відхилить підтвердження, якщо інші запити ще тривають. Після прийняття підтвердження бізнес-операції й авторизація блокуються (503).
4. У серверному терміналі штатно зупиніть Fastify. Не завершуйте сторонні процеси. Запустіть із каталогу HromadaAID, указавши **фактичні серверні шляхи**:

```powershell
pnpm server:backup-restore -- --database "D:\HromadaAID\data\server-test.sqlite" --backup-dir "D:\HromadaAID\backups"
```

5. Команда створює окрему страхову копію, перевіряє її, закриває SQLite, замінює файл через перейменування та перевіряє результат. Початковий файл також зберігається поруч із базою як `.before-restore-…`. Вони містять персональні дані: не переміщуйте їх у загальнодоступні папки.
6. Після повідомлення про успіх запустіть Fastify зі звичною конфігурацією. Усі користувачі входять повторно. Старі сесії, зокрема відновлені з архіву, видалено.

Fastify та CLI використовують спільне міжпроцесне блокування. Перед застосуванням цієї функції потрібно штатно перезапустити сервер на новій збірці; старі версії цього блокування не мають. Не запускайте інші інструменти, що відкривають серверну SQLite, під час відновлення.

Якщо процес перервано або втрачено живлення, **не запускайте Fastify й не видаляйте службові файли**. Повторіть ту саму команду без `--archive`. Журнал дозволяє завершити перейменування та перевірку; неоднозначний або пошкоджений стан блокує запуск і потребує перевірки адміністратором. Страхова копія та початковий файл не очищаються автоматично.

## Втрата сервера або окремий ключ старого архіву

Збережіть `.hraid` та аварійний ключ окремо. Старий DPAPI-файл не потрібен. На новому сервері встановіть ту саму або сумісну версію HromadaAID, створіть ізольовану серверну базу та першого адміністратора звичайними командами, потім зупиніть Fastify. Відновлювана копія повинна містити активного адміністратора з відомими вам обліковими даними.

```powershell
pnpm server:backup-restore -- --database "D:\HromadaAID\data\server-test.sqlite" --backup-dir "D:\HromadaAID\backups" --archive "E:\Recovery\backup.hraid" --recovery-key
```

Ключ запитується приховано в інтерактивному терміналі; не передавайте його аргументом команди. Перед підтвердженням буде показано дату (для формату 1 дата в архіві відсутня). Команда приймає формати 1 і 2, точну поточну схему 28 та відому попередню схему 27 з наступною штатною міграцією кандидата. Невідомі, давніші або майбутні схеми відхиляються; зміни робочої бази до перевірки не виконуються.

Для незалежного розшифрування без заміни бази збережено команду:

```powershell
pnpm server:backup-decrypt -- --input "E:\Recovery\backup.hraid" --output "D:\Recovery\separate-test.sqlite"
```

Новий файл не повинен існувати. Передавайте лише перевірені архіви. Для відновлення й подальшого створення архівів на новому сервері налаштуйте серверний ключ окремою штатною командою; ключ ніколи не передається Electron.

## Межі

- Максимальний завантажуваний файл — 2 ГіБ; неперервне потокове передавання обмежене п’ятьма хвилинами на клієнті.
- Перевірка перед підтвердженням чинна 30 хвилин. Прострочені непідтверджені кандидати прибираються під час наступної підготовки.
- Серверні ручні й страхові копії не входять до ліміту 14 щоденних; автоматичного видалення ручних/страхових копій немає. Контролюйте вільне місце.
- Підтвердження в GUI не замінює завершення CLI. Гаряча заміна відкритої SQLite не виконується.
- Захист від збоїв не замінює справного диска, захищених прав Windows на каталог бази й копій та окремого аварійного ключа.
