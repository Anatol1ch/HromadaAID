# Казначейські відомості у portable Client

## Підтверджений дефект

`StatementFormation.tsx` викликає `window.hromadaAid.statements.generate`.
Ізольований preload передає типізований запит `statements:generate` до Electron main.
Обробник отримує snapshot із API, перевіряє параметри, створює власний тимчасовий
каталог та копіює шаблон. PowerShell отримує JSON через stdin; Excel відкриває
лише цю копію, заповнює клітинки, зберігає XLSX (для персональної форми також
справжній BIFF8 XLS), експортує PDF. Preview читає створений PDF; окремі IPC
збереження копіюють результати у вибране користувачем місце.

У попередньому portable усі три PowerShell-скрипти та шаблони були в `app.asar`.
Electron `copyFileSync` може прочитати шаблон через свою віртуальну файлову систему.
Зовнішній `powershell.exe -File ...\app.asar\...\excel-templates.ps1` не може
прочитати скрипт. Цей виклик відтворено на попередньому пакеті: PowerShell повертає
`-196608` і повідомлення про відсутній аргумент `-File`, до активації Excel COM.
Обробник раніше перетворював цей збій на загальне повідомлення про Excel/PDF.

Тепер electron-builder розпаковує `excel-*.ps1` у фізичний
`resources/app.asar.unpacked/dist-electron/electron`. Усі три виклики використовують
цей шлях. Шаблони залишаються в ASAR; їхня структура не змінена. Portable pipeline
перевіряє актуальність усіх скриптів та побайтовий збіг трьох шаблонів.

## Діагностика

`statement-export.log` у каталозі журналів Electron містить час, етап, дозволений
код, exit code, signal, тип винятку, HRESULT і номер рядка. Розрізняються підготовка
тимчасового каталогу, копіювання шаблону, stdin, запуск COM, відкриття, заповнення,
збереження XLSX/XLS, експорт і читання PDF. Користувач отримує коротке повідомлення
відповідного етапу. Сирі повідомлення PowerShell не передаються до журналу чи UI:
вони можуть містити шляхи, назви файлів або дані клітинок.

## Культура та кодування

- React передає перевірені ISO-дати; main формує `ДД.ММ.РРРР` через зрізи рядка.
  PowerShell записує дати як текст у клітинки з `NumberFormat = '@'`.
- Суми надходять зі snapshot як цілі копійки; перед записом формуються JSON-числа.
  `ConvertFrom-Json` та явний `[double]` перед `Value2` не використовують парсинг
  локалізованого рядка суми. Підсумки вибірки й бізнес-правила не змінені.
- stdin містить ASCII JSON з Unicode escape-послідовностями. Скрипти з українським
  текстом мають UTF-8 BOM, що перевіряється у сформованому пакеті під PS 5.1.
- `FormulaLocal` і локалізовані назви функцій не використовуються. Формули й стилі
  казначейських шаблонів збережені. У банківському/звітному генераторі
  `NumberFormatLocal` будується з фактичних `Excel.International` separators.
- Персональний шаблон використовує General для суми, зведений — `#,##0.00_₴`.
  Видимі роздільники чисел можуть залежати від Excel/Windows. Це окремий ризик
  представлення, а не причина відтвореного збою запуску скрипту. Не змінюємо стилі
  або глобальні separators без порівняння реальних документів у цільових середовищах.

## Перевірки та повторний тест VM

Зібрати: `pnpm client:portable`. Запустити тести:

```powershell
node --import ./tests/source-loader.mjs --test tests/excel-worker.test.mjs tests/statement-parameters.test.mjs tests/statement-filenames.test.mjs tests/report-export.test.mjs
node --test tests/packaged-excel.test.mjs
node scripts/test-document-transport.mjs
pnpm client:portable:smoke
```

Повний тест Excel/PDF є явним opt-in: `$env:HROMADA_TEST_EXCEL='1'` та
`node --test tests/excel-statement-parameters.test.mjs`. Він використовує
запакований фізичний worker, виключно синтетичні тимчасові копії та окремі COM
екземпляри. `en-US`/`uk-UA` застосовуються лише до дочірнього тестового процесу.
Тест перевіряє справжній XLS, XLSX, PDF, числові дробові суми, українські імена,
ведучі нулі і дати. Це не емуляція англомовної Windows чи іншої версії Office.

У VM розпакувати новий ZIP в окремий каталог; не переносити лише EXE. Запустити
клієнт звичайним користувачем, підключитися до тестового сервера, вибрати синтетичні
призначення з сумами 1234,56 і 0,44 та сформувати персональну й зведену відомості
з датою 29.02.2028. Зберегти результати під новими іменами, перевірити суми,
кирилицю, ведучі нулі, PDF та відповідність дат. Для повного порівняння відображення
сум повторити той самий сценарій у VM/профілях з en-US і uk-UA; не змінювати
глобальні налаштування Excel як спосіб виправлення. При помилці надати лише
`statement-export.log`; документи й персональні дані для діагностики не потрібні.
