# HromadaAID

HromadaAID — настільна клієнт-серверна система обліку матеріальних допомог для
органів місцевого самоврядування. Інтерфейс користувача українською мовою.

## Компоненти

| Компонент | Призначення |
| --- | --- |
| HromadaAID Client | Робота працівників із реєстрами та документами через API |
| HromadaAID API Server | Бізнес-операції, автентифікація, SQLite та серверні резервні копії |
| HromadaAID Server Manager | Локальне адміністрування встановленого сервера |
| Єдиний Windows Setup | Client-only, Server-only (API + Manager), Combined; Modify/Upgrade/Uninstall |

## Наявні можливості

- Облік отримувачів, банків, рішень і призначень матеріальної допомоги.
- Довідники, річне планування, звітність і формування платіжних відомостей.
- Формування Excel-документів через Windows Excel COM та наявні шаблони.
- Облікові записи, ролі й обмеження доступу до операцій.
- Ручне налаштування й збереження адреси сервера в Client: HTTP з IPv4 або DNS-ім'ям
  на фіксованому порту 4310, через loopback, LAN або Tailscale. Повторне підключення
  використовує ту саму адресу; автоматичного пошуку й перемикання серверів немає.
- Первинне налаштування сервера, контроль служби/API, резервування,
  ZIP-оновлення та контрольоване recovery через Server Manager.
- Обов'язкові Stable GitHub оновлення Client/Manager через універсальний Setup
  та завантаження Server ZIP через чинний транзакційний updater.

Client не має автономної робочої SQLite або адміністративного резервування.
Старі клієнтські backup-файли залишаються на диску й автоматично не мігруються.

Один API Server слухає IPv4 `0.0.0.0:4310` і працює з однією серверною SQLite.
Внутрішнього TLS немає; LAN HTTP не шифрує дані. Tailscale забезпечує тунель як
зовнішній інструмент: HromadaAID ним не керує й не налаштовує Windows Firewall.
Server Manager показує loopback, доступні LAN IPv4 та визначений Tailscale-адаптер
лише на основному екрані. Серверна конфігурація має єдиний формат v3 з полями
`programDirectory`, `databasePath`, `backupDirectory`; несумісний файл не мігрується
й не переписується автоматично. HTTPS зовнішніх сервісів збережено.

## Поточний стан

Stage 9.5.1–9.5.3 функціонально прийнято власником після ручного тестування. Production Release v1.0.0 підготовлено. На момент release commit публікація очікує GitHub Actions; попередній підтверджений Stable — v0.2.2. Фактичний стан: [GitHub Releases](https://github.com/Anatol1ch/HromadaAID/releases).

МФО — автоматично рівно 6 цифр, ЄДРПОУ — автоматично рівно 8 цифр, із блокуванням збереження на клієнті й сервері. Контрольний розряд ЄДРПОУ не перевіряється. IBAN — добровільно кнопкою за українським форматом і MOD 97, без нових блокувальних правил.

Відоме некритичне обмеження, підтверджене на Windows VM у 0.2.1: Server Manager
може некоректно визначати або показувати LAN/Tailscale IPv4 у деяких конфігураціях
Windows VM. Це не перешкоджає
підключенню Client; адресу сервера можна ввести вручну. Власник прийняв обмеження,
окреме виправлення не планується. Наступний етап — Stage 9.5;
поточний checkpoint — у [HANDOFF.md](HANDOFF.md), план — у [ROADMAP.md](ROADMAP.md).

Технічні межі: [ARCHITECTURE.md](ARCHITECTURE.md). Подальша робота:
[ROADMAP.md](ROADMAP.md). Актуальний checkpoint і перевірки: [HANDOFF.md](HANDOFF.md).
