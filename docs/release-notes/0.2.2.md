# HromadaAID v0.2.2

Технічний реліз об'єднує очищення проєкту Stage 9.3 та автоматизацію релізів
Stage 9.4. Це перший реліз, підготовлений для автоматичної збірки й публікації
через GitHub Actions після push у `main`.

- Перед Server build очищується лише generated `dist-server`, щоб застарілі
  скомпільовані модулі не потрапляли до нових пакетів.
- Виправлено шлях пакетного installer-тесту, видалено невикористаний Client
  helper резервування та актуалізовано технічну документацію.
- Додано `pnpm release:package`: Universal Setup, Server ZIP із того самого
  Server payload і release manifest із перевіркою цілісності.
- Закріплено Node.js 24.22.1 та pnpm 11.25.0. Windows x64 комплект формується
  в GitHub Actions; перед Stable publication перевіряються всі три assets.
- Наявні версії й теги не перезаписуються; ручний запуск workflow виконує лише
  збірку. Неповний Release після помилки завантаження залишається Draft.

Оновлення з 0.2.1 використовує чинні механізми: Client і Server Manager —
Universal Setup; API Server — Server ZIP через Server Manager відповідної версії.
Збережено три режими Setup, серверну конфігурацію v3, HTTP transport Stage 9.2,
SQLite та чинні installation/update/recovery contracts.

Очікувані файли релізу:

- `HromadaAID-Setup-0.2.2.exe`;
- `HromadaAID-Server-v0.2.2-win-x64.zip`;
- `release-manifest.json`.

Статус підготовки: перший повний build і publication на GitHub Windows runner,
а також приймання оновлення 0.2.1 → 0.2.2 у Windows VM ще не підтверджені.
Відоме інформаційне обмеження визначення LAN/Tailscale IPv4 у Manager залишається.
