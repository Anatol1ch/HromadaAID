# Stage 7: архітектура, перевірки інтерфейсу та передумови Stage 8

## Межі компонентів

Єдиний маршрут робочих даних: Client → типізований IPC → HTTP API → Server → SQLite.
Electron main виконує мережеві запити, зберігає стан сесії та адресу підключення,
керує локальним Excel COM і збереженням документів. Renderer ізольований від Node.js.
Відсутність API або старе налаштування `HROMADAAID_MODE=local` не відкриває SQLite.
Стара SQLite в профілі клієнта не читається, не видаляється й не мігрується автоматично.
Некоректний старий файл налаштувань залишає доступним налаштування адреси сервера.

Цільовий аналіз імпортів підтвердив, що живого Legacy Local Mode на початку Stage 7
вже немає: всі модулі `electron` досяжні з Client або Server, а клієнтський граф не
імпортує SQLite. `electron/*-store.ts`, `database.ts`, міграції та SQL read-моделі
використовує Server; видалення їх порушило б бізнес-логіку. Renderer repositories
є чинними обгортками API через IPC. Вони збережені. Залежності SQLite у клієнтській
production-збірці додатково забороняє `scripts/test-client-server-only.mjs`.

Локальна адреса підключення, сесія, експортовані документи й завантажені резервні
архіви на клієнтському ПК не є локальним сховищем робочих реєстрів. SQLite на
серверному ПК та локальний HTTP між Client і Server на одному ПК залишаються
коректними поняттями. У текстах реєстрів і формування документів вживаються
«серверні дані» та «база даних сервера».

## Мережа та Tailscale

- Адреса задається користувачем у налаштуваннях, збереженим URL або керованою
  змінною `HROMADAAID_API_URL`; продуктивний API не зашитий як константа.
- HTTP дозволений для `localhost`, `127.0.0.1`, `::1`. LAN IPv4, DNS-імена,
  Tailscale IPv4 і MagicDNS дозволені через HTTPS. Зміна цієї політики не потрібна.
- Server `mode=network` налаштовується адміністратором явно: адреса на потрібному
  інтерфейсі, порт, наявні сертифікат і приватний ключ. Loopback не змінюється
  автоматично на `0.0.0.0`.
- Сертифікат повинен відповідати імені/IP у клієнтському URL та бути довіреним
  на клієнтських ПК. Не вимикати TLS-перевірку. Сам VPN не скасовує HTTPS-політику
  HromadaAID й не робить довільний сертифікат довіреним.
- Для майбутнього Tailscale потрібні піднятий приватний інтерфейс, дозволений
  маршрут/політика tailnet і порт Windows Firewall лише для потрібних приватних
  джерел. Це майбутнє явне налаштування; Stage 7 його не змінює.
- Автентифікація, RBAC і чинні обмеження запитів зберігаються. Публічний порт,
  перенаправлення на маршрутизаторі чи послаблення CORS не потрібні.

## Ручний GUI-чекліст

Автоматизовані знімки у `release/server-manager-ui-review` використовують тестові
IPC-відповіді, справжній renderer/preload та синтетичні шляхи. Вони не доводять
наявність реального встановленого сервера. Перевірка охоплює чотири розділи й
масштабування 150% без горизонтального переповнення.

У Windows VM перевірити:

1. Запуск максимізованим, видиму панель завдань, відновлення розміру й другий монітор.
2. Масштаби Windows 100%, 125%, 150%; вузьке вікно, довгі Unicode-шляхи, вертикальне
   прокручування до всіх кнопок, клавіатурний фокус і Enter/Space.
3. Стан служби й API показуються окремо; «Running» без відповіді API не є успіхом.
4. «Перевірити стан» після оновлення показує «Перевірка…», блокує повторний клік,
   оновлює відомості та повідомляє про доступність API або помилку.
5. Під час системної операції конфліктні дії недоступні. Підтвердження зупинки
   лишається чинним. Закриття Manager не зупиняє сервер.
6. ZIP-підтвердження чітко показує версії, сумісність і результат/відкат. Перемикання
   між сторінками не повинно запускати системні дії.
7. Іконка із ключем відображається у вікні, панелі завдань і новому EXE. Старі
   закріплені ярлики Windows можуть потребувати повторного закріплення вручну.
8. Клієнтські реєстри й About/налаштування не обіцяють автономної роботи з SQLite.

## Передумови Stage 8

| Напрям | Передумови |
| --- | --- |
| Windows Installer | Окремі appId та іконки, підпис видавця, обмежені права Client і явне підвищення прав Manager; тестування чистого встановлення/видалення у VM |
| Client-only / Server-only / Combined | Доставка незалежних пакетів; Server Manager повторно використовує наявне встановлення, NSIS не дублює ініціалізацію; Combined передає клієнту лише адресу API |
| Автооновлення | Незалежні версії Client/Manager/Server, API compatibility v1 та schema metadata, перевірка автентичності, канали й явна політика перезапуску; готовий ZIP-механізм сервера збережено |
| GitHub Releases | Визначити репозиторій/канал, права публікації CI, підписи, артефакти й update metadata для electron-builder/electron-updater; токени не вбудовувати у Client |
| LAN | Явний network-mode, доступний інтерфейс/порт, довірений TLS і перевірка двома ПК без зміни бізнес-логіки |
| Tailscale | Приватний інтерфейс, tailnet-політика, MagicDNS/IP та відповідний HTTPS; SDK/VPN у застосунок не додавати |

Пакетні SHA-256 підтверджують цілісність, а не видавця. Підписи й автоматичне
отримання релізів залишаються Stage 8. Схеми БД, версії та фінансові правила Stage 7
не змінює. Повторне реальне тестування ZIP-транзакції вже пройшло у VM; тут
перевіряються UI й межі клієнт-серверної роботи.
