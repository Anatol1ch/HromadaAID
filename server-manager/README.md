# HromadaAID Server Manager — D2.3B

Окремі Electron main і React/Vite entry points. Основний застосунок та Fastify не запускаються. Спільними є тільки CSS-токени/примітиви `src/styles.css`, локальний компонент `Alert` та Lucide. Немає preload, IPC, Installation Engine або серверних імпортів.

Команди з кореня репозиторію:

- `pnpm manager:dev` — окреме вікно з Vite/HMR на `127.0.0.1:5176`; закриття вікна завершує dev-сеанс. Зайнятий порт не звільняється примусово.
- `pnpm manager:start` — збірка й автономний запуск через `file://`, без Vite/Fastify. Потрібні лише залежності розробника цього репозиторію.
- `pnpm manager:build` — окремі виходи `dist-server-manager/main/main.js` та `dist-server-manager/renderer`; основна збірка клієнта їх не включає.
- `pnpm manager:test` — типи, збірка, цільові unit-тести та функціональні перевірки справжнього Electron-вікна через `file://` і Vite, у тимчасових профілях. Знімок огляду: `dist-server-manager/preview.png`.

Навігація, вибір шести демонстраційних станів, фільтр діагностики та локальна демоперевірка працюють. Перемикач сценаріїв доступний також в автономній збірці для візуального оцінювання. Усі дані позначені як тестові; системні дії вимкнені з поясненнями. Час оновлюється лише локально. Жодні служби, диски, конфігурації, SQLite чи API не опитуються.

Вікно має окремий профіль `HromadaAID-Server-Manager` у стандартному AppData, власну session partition, sandbox/contextIsolation, заборонені дозволи та нові вікна. Мережа дозволена лише до окремого Vite у dev; автономний запуск дозволяє тільки власні renderer-файли. Electron може створити службовий кеш свого профілю.

`shared/installation-contract.ts` описує майбутні операції незалежно від React. Поле `message` призначене тільки для безпечного тексту: довільний stdout, паролі, токени й ключі передавати заборонено. Типізація сама не забезпечує очищення секретів — це відповідальність майбутнього Engine.

Пакування Server Manager, UAC, керування службою, редагування конфігурації, майстер, аварійний ключ та оновлення ще не реалізовані. D2.3C доцільно почати з незалежного read-only Engine для перевірки стану інсталяції зі структурованими результатами та тестами на ізольованих ресурсах.
