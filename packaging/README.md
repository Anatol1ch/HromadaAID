# Windows server installation flow

The NSIS package offers independent Client and Server sections; selecting both installs Server + Client. Program files stay under the selected install directory. Server data defaults to `%ProgramData%\HromadaAID\Data`; backups default to `%ProgramData%\HromadaAID\Backups`. Both can be changed independently, and the installer accepts only separate, local fixed NTFS directories.

New installations store SQLite in `Data\Database\hromada-aid.sqlite`, configuration at `Data\server.json`, and WinSW logs at `Data\Logs`. Existing compatible configurations retain their database path, including the earlier `Data\hromada-aid.sqlite` layout. The LocalService service SID receives read/execute on server files, modify on the SQLite and log directories, and backup access. Configuration and the DPAPI key receive explicit service read-only ACLs plus an explicit deny for service write/delete. Administrators and SYSTEM retain administrative access. Parent directories are not re-ACL'd. The installed API uses the fixed internal HTTP transport on port 4310; see [server/TRANSPORT.md](../server/TRANSPORT.md).

Before registering or starting a service, the installer validates the selected paths, installed configuration, database/DPAPI/archive state, and writable storage. A clean first install displays the newly generated emergency recovery key in a confirmation dialog. The administrator must save it offline before database and DPAPI initialization continues. The key uses the existing DPAPI LocalMachine scope. Existing database + key pairs are retained and checked; mismatched states, archives without a key/database pair, or incompatible configuration stop installation without replacement.

WinSW 2.12 registers `HromadaAIDApi` under LocalService. The installer enables the unrestricted service SID with `sc.exe sidtype`, applies ACLs, performs explicit first initialization only for a clean state, then starts the service and verifies the Fastify health response. The API listens on the fixed internal HTTP port 4310. The combined Client + Server install adds an immutable, non-secret packaged default `http://127.0.0.1:4310`; an existing per-user client address continues to take precedence.

For upgrades, the previous service is stopped before its files are replaced. Since WinSW 2.12 has no `refresh` command, the installer unregisters and re-registers the service using the updated XML. It records whether the old service was running and attempts to restore registration/state if an install step fails. Ordinary uninstall stops and unregisters the service, then removes program files only; SQLite, configuration, logs, DPAPI key, backups, and stored install paths remain in their selected locations.

This repository stage does not run an installer or modify the current machine's services, ACLs, or firewall. A power loss during the short interval between service unregister/register or during initial key/database publication can leave a service stopped or an incomplete data pair. The next run fails closed and preserves files; an administrator must inspect logs/state before manually resuming. Verify these interrupted-install cases, the actual LocalService ACLs, DPAPI read access, port conflicts, startup recovery, and uninstall preservation on a disposable Windows 10/11 VM before release.
