# HTTP-транспорт сервера HromadaAID

API Server використовує один Fastify instance, одну серверну SQLite та єдиний
IPv4 HTTP listener на `0.0.0.0:4310`. Адреса й порт фіксовані; `server.json`
і змінні середовища не можуть їх змінити. Якщо порт зайнятий, запуск завершується
з діагностикою про зайнятий порт 4310; іншого порту або listener сервер не створює.

Один сервер одночасно приймає запити через:

- Loopback: `http://127.0.0.1:4310`.
- LAN: `http://<LAN-IP>:4310`.
- Tailscale: `http://<TAILSCALE-IP>:4310`.

`0.0.0.0` — адреса прослуховування, а не адреса для налаштування Client.
IPv6 listener не створюється. Зміна LAN IPv4 або поява Tailscale-інтерфейсу після
старту не потребують повторного bind чи перезапуску API. Сервер не перевіряє
наявність Tailscale й не залежить від його запуску; SDK, керування tailnet,
автоматичного встановлення, discovery та reverse proxy немає.

Внутрішнього TLS немає: сервер не завантажує сертифікати й ключі для API.
Звичайний LAN HTTP не шифрує запити; Tailscale забезпечує шифрований тунель між
вузлами tailnet. Authentication, Argon2id, sessions, RBAC, server-side authorization
та login rate limiting збережено. Бізнесові й адміністративні `/api/*` маршрути
вимагають сесію та відповідні дозволи незалежно від адреси клієнта; `/health`
залишається публічним і перевіряє доступність SQLite через `SELECT 1`.
HTTPS зовнішніх сервісів, зокрема GitHub Releases та завантаження оновлень,
цією зміною не зачіпається.

Доступність через LAN/Tailscale залежить від Windows Firewall, маршрутизації та
політик tailnet. Wildcard bind відкриває listener на всіх наявних IPv4 інтерфейсах;
дозволені джерела мережевого доступу визначаються зовнішніми правилами. Сервер не
створює й не змінює правила Windows Firewall. Перевірка HTTP через локальну адресу
інтерфейсу не замінює приймання з іншого комп'ютера або вузла tailnet у Windows VM.

## Актуальна конфігурація

Єдиний формат — configVersion: 3 з полями programDirectory, databasePath та
backupDirectory. Приклад — [installed-config.example.json](installed-config.example.json).
Параметри HTTP, 0.0.0.0 і 4310 зафіксовано в server-runtime.ts, а не в server.json.
Версії 1/2, невідомі поля та mode/host/port/tls відхиляються як несумісні.
Автоматичного очищення, переписування або міграції старої конфігурації немає.

Сервер читає `server.json` без перезапису, видалення чи скидання. Зберігаються
`programDirectory`, `databasePath`, `backupDirectory`; шлях Logs і далі задає
чинний WinSW XML. Неправильні нетранспортні параметри, невідомі поля/версії,
некоректний JSON та недоступні шляхи залишаються помилками. Транспортна зміна не
додає міграцій SQLite. Development/test entry point зберігає вимогу окремої бази
з `test` у назві, але використовує той самий фіксований HTTP transport.

Модель служби не змінена: `HromadaAIDApi`, WinSW, LocalService, явний
`installed.js --config <server.json>`, чинні каталоги ProgramData й graceful stop.

## Client, Manager та інсталятор

Client приймає базову HTTP-адресу з IPv4 або DNS-ім'ям і портом 4310. Адреса
зберігається чинним механізмом; недоступність не видаляє її. HTTPS-адреса
відхиляється; автоматичної конвертації або fallback до іншого сервера немає.
Нова адреса проходить health-check перед збереженням. Redirects
заборонені; API-шлях не може змінити origin запиту.

Manager перевіряє лише http://127.0.0.1:4310/health після перевірки актуальної
конфігурації. Стан SCM і стан API перевіряються окремо.
У 1.0.1 блок адрес містить вручну задані Loopback, LAN і Tailscale з кнопками
Copy → Pencil. Значення зберігаються в окремому server-addresses.json профілю
Manager; автоматичний збір Get-NetAdapter/Get-NetIPAddress вилучено.
HTTP IPv4/DNS на порту 4310 перевіряється спільним із Client валідатором;
Loopback обмежений 127.0.0.1/localhost, LAN/Tailscale можуть бути незаданими.
Збереження не перевіряє мережеву доступність і не змінює listener, server.json
або Client. Пошкоджені/несумісні налаштування не скидаються автоматично.
Копіювання має вузький IPC за ключем позиції з перевіркою довіреного renderer.
Редаговані адреси не підміняють фіксований локальний HTTP health-check.
Адміністративні повноваження, service controls і захист backup/restore не змінені.

Universal NSIS зберігає Client-only, Server-only і Server + Client. Генератор
створює лише актуальну конфігурацію; preflight відхиляє несумісну до створення
серверних даних або змін служби. Installation/update/recovery використовують
фіксований локальний HTTP health URL; TLS-файли не створюються й не перевіряються.
WinSW, LocalService, service SID, ACL даних/ключів, DPAPI, integrity manifests,
пакетні транзакції, schema compatibility та загальний rollback збережено.
Окремих сценаріїв повернення до старого HTTPS-транспорту немає.

Майстер має три кроки: каталоги, адміністратор, підсумок. Транспортних налаштувань
і мережевого кроку немає. На завершенні показуються стани служби/API й версія;
адреси з копіюванням доступні лише в основному розділі «Стан сервера» Manager.
