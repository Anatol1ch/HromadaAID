# Іконка HromadaAID

Server Manager має окремі `hromadaaid-server-manager.svg/png/ico`: великий білий
гайковий ключ на фірмовому фоні #286343, без HeartHandshake, написів або бейджів.
Геометрію ключа адаптовано з уже встановленого Lucide (ISC), із заповненням та
товстими контурами для малих розмірів. SVG — єдине джерело PNG та всіх кадрів ICO.
Геометрія Client та його файли не змінюються. ICO містить 16/24/32/48/64/128/256 px;
PNG — 512 px. Відтворення: `node scripts/generate-manager-icons.mjs` (потрібні
лише наявні build-залежності Electron; використовується ізольований тимчасовий
профіль, який видаляється після генерації). Ця команда створює лише ресурси іконки.
`server-manager/electron-builder.yml`
задає іконку EXE та майбутнього NSIS, `main.ts` — вікна/панелі завдань. Portable
містить файли у `resources/assets`, без залежності від шляху всередині ASAR.

`hromadaaid.svg` точно відтворює графічний знак сайдбару: `HeartHandshake` з наявного `lucide-react`, 22×22 у квадраті 42×42, strokeWidth=2.1, білий колір, фон #286343, радіус 12. Текстове найменування поруч із знаком не входить до іконки.

- PNG: 512×512, прозорі кути, пропорції SVG збережено.
- ICO: окремі кадри 16, 24, 32, 48, 64, 128, 256 px.
- SVG: масштабований вихідний ресурс.

Ресурси готові й не потребують генерації під час запуску. `electron/copy-assets.mjs` копіює всі три файли до `dist-electron/electron/assets` для Electron runtime та зберігає сумісну копію в `dist-electron/assets` для чинних перевірок. У майбутньому пакеті extraResources копіює іконки поза ASAR до resources/assets, звідки їх читає main. Це забезпечує звичайний файловий шлях для нативного Windows-завантажувача ICO.

У `package.json` додано конфігурацію electron-builder для Windows EXE, NSIS та ярликів. AppUserModelID збігається з main.ts: local.hromadaaid. Ключі конфігурації звірено зі стабільною схемою electron-builder 26.18.0. Пакування використовує electron-builder із чинного lockfile; Stage 7 не створює інсталяторів. Перед майбутнім пакуванням потрібно виконати звичайну збірку застосунку. Назву package та userData не змінено.

У dev використовується виконуваний файл Electron, тому його власна іконка у Провіднику або старий вручну закріплений ярлик Electron можуть залишатися стандартними. Іконка головного вікна задається безпосередньо, а майбутній Windows EXE та створені NSIS ярлики отримуватимуть ICO з конфігурації пакування.

## Windows-ідентичність та ярлики

Стабільні AppUserModelID: Client — `local.hromadaaid`, Manager —
`local.hromadaaid.server-manager`. Вони збігаються в Electron main,
electron-builder та ярликах і не змінюються між оновленнями.
`manager-version.ini` додатково містить `brandingId` (SHA-256 ICO з того самого SVG).
NSIS пропускає копіювання Manager тільки за збігу версії та цього маркера: новий
брендинг потрапляє в EXE, ASAR і ресурси навіть під час тестування одного SemVer.

Єдиний NSIS зберігає загальну іконку продукту в `assets/hromadaaid.ico` каталогу
встановлення незалежно від вибраних компонентів. Єдиний запис Installed Apps
`HromadaAID` використовує саме цей ресурс; Server-only не залежить від Client EXE.
Setup і Uninstall також використовують фірмову іконку Client.

`packaging/windows-shortcuts.ps1` обслуговує тільки два точні імені ярликів
у спільних меню «Пуск» і робочому столі. Native IShellLinkW зберігає Unicode-шляхи,
цільовий EXE, робочий каталог, власну іконку EXE та AppUserModelID через IPropertyStore.
Перед оновленням або видаленням перевіряються ціль, аргументи та наявна ідентичність.
Старі ярлики цього EXE без AppUserModelID оновлюються. Сторонні, пошкоджені,
недоступні ярлики, reparse points та ярлики з користувацькими аргументами
зберігаються з повідомленням у деталях інсталятора. Персональні закріплення
на панелі завдань і ярлики в профілях користувачів не змінюються.

Після майбутнього пакування потрібно перевірити нативні іконки EXE, групування
одночасно відкритих Client/Manager, ярлики обох компонентів у трьох режимах,
Modify/Reinstall та Installed Apps у Server-only. Старі закріплені Windows ярлики
можуть зберігати кеш попередньої іконки; автоматичне очищення кешу не виконується.
